# Windows/Linux Bug 排查与修复 · 2026-10-29

修复代码：`5d81cb2`，分支 `codex/desktop-macos-parity`。排查覆盖 Windows/Linux 共用的键盘与系统菜单路由、AI 设置、拖入文件、窗口缩放、重启恢复，以及原有绘图和文件操作回归。原生 macOS 未改动。

| 已复现问题 | 影响与修复 |
|---|---|
| 弹窗未统一阻止背景操作 | AI 设置打开时，Delete 可删除背后图层，系统菜单的删除／新建／关闭等命令也能穿透部分弹窗；拖入图像可直接增加图层。将 AI 设置纳入共用弹窗状态，统一阻止背景键盘、菜单、文件命令、拖入及新的外部变化检查，打开弹窗时暂停动画。输入框里的文字复制／粘贴／撤销保留。 |
| 弹窗焦点与关闭不完整 | 文字弹窗的第一个 textarea 未进入 Tab 循环，Shift+Tab 能逃出；AI 设置没有完整接入 Escape 和焦点恢复。补全焦点遍历、初始焦点与关闭后的焦点恢复。 |
| 按钮上的空格误触发播放 | 动画项目中，聚焦“适合窗口”等按钮后按空格，会启动动画并阻止按钮原有动作。让按钮、链接、summary 等交互元素处理自己的空格，保留画布区域的播放快捷键。 |
| AI 面板高度未适应窗口变化 | 在大窗口拉高面板后缩小窗口，输入框、底部工具和属性区会被挤出或裁切。按当前窗口限制实际面板高度，保留用户期望高度；提高可用最小高度，给属性区保留滚动空间，支持重启恢复。 |

新增 7 个端到端回归场景。修复前分别保留键盘／原生命令穿透、文字焦点、小窗口 AI、空格播放及拖入图像的失败记录；实际观察包括图层从 2 变为 1、从 2 变为 3，以及 AI 输入框可见比例为 0。最早探针里的两处测试定位器错误已更正，并在旧应用上重新复现对应真实问题，未将定位器错误算作产品缺陷。
