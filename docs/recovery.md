# Local recovery copies

The sandboxed app stores recovery packages in `~/Library/Containers/com.wonderassembly.compositor.zh-Hans/Data/Library/Application Support/com.wonderassembly.compositor.zh-Hans/Recovery/`. Unsandboxed command-line runs use `~/Library/Application Support/com.wonderassembly.compositor.zh-Hans/Recovery/`; these are separate stores. A completed edit, undo or redo captures an immutable committed snapshot and schedules a write after two seconds of inactivity. Continuous editing cannot reset the maximum ten-second wait. A later gesture or modal preview does not block writing the last committed snapshot, and its unfinished pixels are never captured. Images and metadata encode off the main actor; concurrent writes are serialized and coalesce newer committed revisions.

Each UUID-named `.comp` package includes the normal project manifest and images plus `recovery.json`: recovery schema version, project version, document ID, history revision, original path, title, date and normal-close flag. Ordinary project saves omit this extra file. Ordinary session snapshots use project format version 13; snapshots with editable filters or saved Liquify use version 14, or version 15 for channel-screen halftone recipes. Versions 1–15 remain readable through ProjectStore. Recovery schema version 1 is unchanged.

Recovery writes encode only changed image resources. Unchanged image identities and matching filter JSON are reused through immutable hard links into a fresh sibling staging package. Manifest and recovery metadata describe a complete snapshot, not a command journal. Existing resource bytes are checked against SHA-256 digests before reuse; the first replacement after launching uses full project validation. Hashing still reads PNG bytes, and changed displacement/LUT JSON still needs encoding. Weak image references keep the reuse index from retaining a second document.

Once all resources pass the capacity check, `renameatx_np(RENAME_SWAP)` atomically exchanges the old and staged packages on supported macOS filesystems. A first checkpoint uses `RENAME_EXCL`. There is no two-rename fallback: a failed commit keeps the previous package and reports the error. A process interruption leaves the committed path holding either the complete old or complete new package. Private staging remnants are removed on the next replacement only after the committed copy validates. These guarantees concern process interruption; power loss and faulty storage are not claimed to preserve every recent write.

Recovery never calls `markSaved`, changes a document's path, or adds a recent-file entry. A restored draft receives a fresh document ID and is explicitly dirty. Its source is removed only after a replacement recovery copy has been written successfully. A failed replacement keeps the source.

Limits are 32 document identities and 4 GiB of package file contents, counting logical file sizes even when resources share disk blocks. Writes never evict existing copies. Damaged or unsupported packages remain available for manual review and explicit deletion. Failed writes surface a message in the workspace and retain the pending committed state for retry. The message distinguishes the document count limit from the byte limit. The banner links directly to recovery management and offers Retry Recovery; the management sheet shows the current count. Closing the sheet retries failed checkpoints across open tabs, including inactive tabs, without creating a new edit or clearing the unsaved marker. If space is still unavailable, the failure remains visible. No existing copy is deleted automatically.

Normal quit or tab closure first flushes pending completed edits, then marks the copy as normally closed. A failed flush does not mark it closed. Copies remain accessible from File > Recovery Copies. Startup offers review for unclosed, unsupported or damaged entries. The two/ten-second values bound scheduling, not PNG encoding and disk completion time. A long-running unfinished gesture is recoverable only to its preceding committed checkpoint. Recovery does not include unsubmitted text, path or Liquify workspace drafts, and does not guarantee the exact step immediately before a crash.

## 中文摘要

编辑完成后空闲 2 秒备份；连续编辑最长等待 10 秒就安排一次检查点，再加实际编码和写盘时间。保存最近已经完成的编辑，不把正在拖动或预览的中间状态写进去。未变图像复用，只编码变化的资源；恢复副本仍是一份完整的原生项目，包含可编辑滤镜、液化网格和冻结区域。正常关闭会先补写最后一次完成的编辑。崩溃后恢复到最后成功写入的检查点，不能承诺完全不丢最后一步。
