# macOS 颜色模式与位深后续方案

## 当前范围

40.22 提供整图灰度副本、RGB/灰度半调。现有工作文档仍为 sRGB、8 位 RGBA；已有 ICC CMYK 软打样与 CMYK TIFF 导出。截图中的完整灰度、CMYK、Lab、位图、索引颜色、双色调、多通道，以及 16/32 位文档不属于已完成能力。

这份方案仅规划 macOS。Windows 继续使用自己的像素引擎、桥接版本与发行渠道；跨平台互通按能力表单独验收。

## 第一步：颜色与存储基础

建立 `DocumentColorModel`、`PixelFormat` 和明确的 ICC 配置：模型、通道数、整数/浮点类型、位深、alpha 约定、工作空间与显示变换分别记录。不能通过改菜单文字或扩大中间缓冲宣称支持高位深。

逐项盘点 BrushRaster、C 像素函数、Core Image/Metal 合成、蒙版/选区、历史、缩略图、项目资源、PSD 与普通导出中固定的 8 位 RGBA 假设。为每种模型/格式建立操作能力表；未适配功能明确拒绝或要求用户创建转换副本，不可静默量化成 8 位。

项目格式以版本递增加入真实的颜色描述与资源编码；图片、恢复副本与历史快照共同使用这些字段。继续读旧版 sRGB PNG，普通旧能力项目尽量维持原版本。对未知新模型拒绝打开，不能将通道重新解释为 RGB。

## 第二步：完整灰度文档与 16 位

先做 Gray 8 与 RGB/Gray 16 位整数：

- 灰度是文档约束，画笔、文字、形状、填充、图层样式、调整层、导入与滤镜都遵守单通道语义；转换时明确是否合并图层、如何处理不兼容的调整与效果。
- 保留/转换 ICC，支持往返保存、撤销重做、自动恢复；RGB 转灰度丢失的颜色不能通过切换回 RGB 自动恢复，撤销与原项目副本用于恢复。
- 16 位必须贯穿资源、画笔、滤镜、合成、历史和导出。蒙版精度单独定义，不把 8 位蒙版扩容当作高位深图像实现。
- 先支持明确适配的操作；增加内存预算与分块处理。输出 PNG/TIFF/PSD 等格式时检查实际样本精度。

## 第三步：ICC CMYK 与 Lab

复用现有 ICC 读取、转换与打样经验，新增真正的四墨色/三 Lab 分量存储，设计通道面板、取色器、配置文件指定/转换、渲染意图与色域提示。图层混合、透明度、滤镜和调整层需按模式定标；现有 RGB 印刷模拟不能充当 CMYK 文档。

PSD/TIFF 的读写必须声明实际颜色模型、配置文件及通道数据。Lab 的数值范围与编码单独定义，不能把 sRGB 数据改名为 Lab。首版可限制部分编辑能力，界面需解释转换后会发生什么。

## 第四步：索引、位图与专色模型

| 模型 | 必须新增的结构 | 交付前需要确定的行为 |
| --- | --- | --- |
| 索引颜色 | 调色板、透明索引、量化与抖动、索引像素 | 图层是否合并、调色板编辑、导入导出 |
| 位图 | 1 位像素、阈值/扩散/半调网屏、输入输出 DPI | 重采样规则、圆/椭圆/线网点、转换限制 |
| 双色调 | 灰度底图、每墨色曲线及专色描述 | 屏幕模拟、印刷互通、转换与丢失提示 |
| 多通道 | 任意命名通道、专色与覆盖率、通道顺序 | alpha 与墨色通道区别、文件格式与操作能力 |

这些功能需要新的数据结构，不能靠现有 RGB 滤镜叠加完成。按真实使用需求分别排期。

## 第五步：32 位浮点与 HDR

支持超出 0–1 的场景数值、浮点资源、线性合成和单独的屏幕曝光/显示变换。显示调节不修改原始像素；转为 8/16 位时明确色调映射。逐个适配滤镜、笔刷、历史及 HDR 导出，不通过当前 8 位 PNG 中转。

## 每阶段验收

- 用公开/合成色板、连续渐变、半透明层、混合模式与 ICC 样例定标；检查通道数、样本位深、alpha 与色差。
- 保存重开、恢复、撤销重做、转换副本与导出不静默丢失精度/模式/层级；未知字段或不支持资源明确拒绝。
- 高位深渐变经历多次调整仍保留细阶，CPU/GPU 显示一致；显示代理不能替代原始精度。
- 通过独立读取器及实际图像软件交叉打开，分别记录允许误差和未验证项。
- 按真实格式统计 4K/8K 的工作集、历史与读回副本，覆盖显存不足、取消和过期回调。

以上均为后续实施要求，尚未执行。Photoshop 中各位深支持范围可参考 [Adobe 位深说明](https://helpx.adobe.com/photoshop/using/bit-depth.html)；具体功能表以届时实现与验收为准。
