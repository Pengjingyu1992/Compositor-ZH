## 完整图层与像素剪贴板增量

无选区时复制完整图层/组，可跨项目标签粘贴，并保留文字、填充、效果、蒙版、原始 PNG 和可编辑滤镜资源；组内只复制一次，关联剪贴蒙版重新映射。粘贴产生一个撤销步骤，检查目标文件夹及祖先锁定、项目修订和保留资源预算；不把其他项目文件、恢复状态或绝对路径放进缓存。内部图层快照仅驻留主进程内存，资源上限 128 MiB；系统剪贴板只写 PNG 和随机标识，外部复制替换标识后不再采用旧缓存。

选区像素粘贴回原坐标，外部图像在画布居中，并放在当前图层上方/当前文件夹内；粘贴取消选区，撤销恢复。复制蒙版输出灰度覆盖而非图层彩色图像。新增鼠标测试还发现整像素选框被视口浮点误差多选一列，现仅校正距整数小于 0.001 像素的坐标。

## 静态图片拖入与导入保护

支持最多 32 张 PNG/JPEG/TIFF/WebP/AVIF 的拖入与文件选择器多选，以及其他应用提供的图像 File 数据。已有画布按拖入点放置；没有画布时，第一张图像确定尺寸和 DPI，后续居中。保留源文件顺序、原始 PNG/ICC/方向、目标文件夹和已有选区/锁定。各图像先组成候选项目，全部成功才提交一次可撤销编辑；失败或取消不留下部分图层。显示逐项进度并可取消，取消终止解码工作线程，关闭窗口或渲染进程失效也会取消。单文件 64 MiB、批次源数据 128 MiB，仍检查项目和工作区总预算。

实际操作发现并修复了旧原始 PNG 导入的保护状态丢失：替换资源后重新验证项目时，现在同时保留选区和已有锁定。新旧导入都使用同一放置和资源保留逻辑。确认当前预编译解码器没有 JPEG 2000 支持，移除文件选择器里不可用的 JP2 选项；没有把它列为已实现。GIF/EPS 仍使用单文件导入，PSD 使用独立入口，本增量未宣称支持它们的批量拖入。

236 项单元、类型检查、源码隐私扫描及独立 PSD/Pillow/Ghostscript 读取通过。Linux 实际包六组增量覆盖原生多文件拖入、外部 File 数据、原图/ICC、锁定、单文件/多文件选择器、撤销、取消/失败不变和旧项目文件夹拖入；最终构建完整 77 项及三格式包审查正在完成。此前剪贴板版本本机/云端 Linux 74/74、Windows 云端 71 通过/3 个 Linux 专属跳过（40657179182 / 40657178972）。

## 安装包隐私审查一致性

上述两端云端均通过完整界面检查，随后包审查把生成模块 Base64 中的 `AKIA` 加小写字符误判成 AWS 访问 ID。现在源码与安装包共用相同规则：按真实凭据格式区分大小写，仍扫描全部文本与 Base64 内容；增加临时 AWS ID 及带引号 JSON/含 Base64 字符的明文密钥检查，回归同时验证真实格式会被拒绝、生成模块不会误报。没有忽略文件或关闭审查。安装包内的颜色模块还与固定源文件/编译记录 SHA-256 再次比较，并继续要求零主机导入与完整许可证。

包审查可用 `--gui-report` 指定隔离目录内的实际回归报告，不必覆盖旧结果；明确指定的报告缺失或有失败项会拒绝，默认报告中的失败也不能在缺少有效同构建修正报告时通过。
